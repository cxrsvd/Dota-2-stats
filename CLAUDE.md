# SimpleShowMMR - Dota 2 MMR Tracker

## 📋 Обзор проекта

SimpleShowMMR — настольное приложение для отслеживания MMR (Matchmaking Rating) в Dota 2. Программа подключается к Steam и Dota 2 Game Coordinator напрямую, получает историю матчей и дополняет её статистикой из OpenDota API. Текущая версия — **2.4**.

## 🔧 Технологический стек

- **Фреймворк**: .NET 10.0 (`net10.0-windows`)
- **Тип приложения**: Windows Forms (WinExe)
- **Ключевые библиотеки**:
  - SteamKit2 (NuGet, `3.*`) — авторизация в Steam и обмен сообщениями с Dota 2 GC
  - protobuf-net — приходит транзитивно через SteamKit2, напрямую не подключается
- **Язык**: C#
- **UI**: кастомный тёмный интерфейс, написан вручную (кнопки, переключатель, скроллбар, карточки, выбор цвета). Акцентный цвет по умолчанию красный, пользователь может его менять.

## 🚀 Что делает приложение

1. **Авторизация в Steam** — логин/пароль + Steam Guard, затем зашифрованный refresh-токен (DPAPI). Пароль нигде не сохраняется.
2. **История матчей** — через Dota 2 GC (AppID 570) `CMsgDOTAGetPlayerMatchHistory`: match_id, время, герой, победа, режим, длительность, `previous_rank`, `rank_change`. В таблицу попадают рейтинговые матчи.
3. **Статистика из OpenDota** (последние 40 матчей): K/D/A, GPM/XPM, last hits, hero damage, party size и `leaver_status`.
   - Кнопка «Синхронизировать» (и автосинхронизация) сначала шлёт `POST /players/{id}/refresh`, потом до 4 раз опрашивает API, пока данные не появятся.
   - Матчи без статистики или без `leaver_status` подтягиваются повторно (`MatchEntry.NeedsStats`).
   - Если в Dota 2 выключено «Expose Public Match Data», OpenDota данных не отдаст.
4. **Покинутые игры** — `leaver_status >= 2` показывается как оранжевое «⚠ Покинута» вместо «Поражение». В винрейте такая игра считается по результату команды.
5. **Время и периоды — по Москве (МСК)** — время матчей в таблице в МСК; «сегодня» = с 00:00 МСК, «эта неделя» = с понедельника 00:00 МСК, «этот месяц» = с 1-го числа 00:00 МСК. Период переключается кликом по карточке «ЗА ПЕРИОД».
6. **Интерфейс**
   - Боковая панель: профиль Steam, индикатор Dota 2 (по данным Steam), кнопки «Stratz» и «Dotabuff» (открывают профиль игрока в браузере), «Синхронизировать» и выпадающая вниз панель «Параметры» (автосинхронизация, смена аккаунта, сброс истории, акцентный цвет).
   - Кнопка-«гамбургер» (три горизонтальные полоски) слева от заголовка открывает меню: «История матчей» (таблица) или «Статистика игр» (лучший герой по винрейту, средние K/D/A, GPM, XPM). Статистика считается за период, который переключается кликом по карточке «ЗА ПЕРИОД». Лучший герой — среди сыгранных ≥2 раз (если таких нет — среди всех).
   - Акцентный цвет: 6 готовых + свой через тёмное окно выбора цвета (HSV + HEX). Слишком тёмные цвета не принимаются. Сохраняется в `settings.json` (`AccentHex`).
   - Таблица истории — только для просмотра: без выделения, сортировки, перетаскивания и подсказок. Прокрутка колесом и скроллбаром работает.
   - Четыре карточки: рейтинг, последняя игра, изменение MMR за период, винрейт за период (без полоски).
   - Размер окна по умолчанию 1400×740, минимум 1200×640.
7. **Статус Dota 2 и автосинхронизация** — статус берётся из Steam (`https://steamcommunity.com/profiles/{id64}?xml=1`, блок `inGameInfo`, опрос раз в 15 с), а не из процессов ПК. В настройках приватности Steam «Сведения об играх» должны быть открыты. Во время собственной синхронизации и 30 с после неё опрос игнорируется (наша сессия сама светится как «Dota 2»). Автосинхронизация — через 15 секунд после того, как Steam перестал показывать Dota 2.

## 💾 Хранение данных

Всё в `%AppData%\DotaMmrTracker`:
- `settings.json` — логин, ник, зашифрованный токен, ID аккаунта, автосинхронизация, `AccentHex`
- `data.json` — история матчей (с резервной копией `.bak`)
- `heroes.json` — кеш героев OpenDota
- `icons/` — кеш иконок героев (`{id}.png`)
- `gc_dump.txt` — диагностика ответа GC

## ⚙️ Команды

Команды выполняются в терминале VS Code в папке с `SimpleShowMMR.csproj`.

```bash
# Отладочная сборка
dotnet build -c Debug

# Запуск
dotnet run --project SimpleShowMMR.csproj

# Публикация: один exe, для запуска нужен установленный .NET 10 Desktop Runtime
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true

# Публикация: один exe БЕЗ необходимости ставить .NET (~53 МБ)
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true

# Очистка
dotnet clean
```

Результат публикации: `bin\Release\net10.0-windows\win-x64\publish\`. Для переноса нужны `SimpleShowMMR.exe` и `icon.ico` (`.pdb` не нужен).

## 🤝 Как со мной работать (правила для Claude)

### Общение и процесс
1. **Язык** — отвечать по-русски, коротко и по делу.
2. **Не трогать лишние файлы.** Менять только то, что нужно для задачи. Если не нужно, `GcClient.cs`, `.csproj` и `CLAUDE.md` не править.
3. **Сборку проверяет пользователь.** В среде Claude обычно нет `dotnet`, поэтому код нельзя скомпилировать. Claude честно говорит, что не проверял сборку, перечитывает правки и просит прислать текст ошибки, если она появится.
4. **Выдача результата** — Claude отдаёт изменённый файл целиком (обычно `Program.cs`) и кратко перечисляет, что изменилось. Если пользователь прислал свою версию файла, Claude берёт её за основу, не откатывая его правки. Спорные расхождения (например, вернулась уже убранная деталь) он называет прямо.
5. **Форматирование файлов** — сохранять кодировку UTF-8 и переносы строк, какие были в присланном файле (раньше CRLF, версия пользователя может быть с LF).
6. **Неоднозначные требования** — выбрать разумную трактовку, прямо её назвать и предложить поменять (например, «периоды по календарю, а не скользящие»).

### Код
1. **Тема и стиль.** Цвета берутся из `Theme`. Не хардкодить красный: акцент берётся из `Theme.Accent`/`Theme.AccentHi`, а при смене цвета нужно обновлять все места, где он сохранён (см. `MainForm.ApplyAccent`). Новые контролы — в той же кастомной стилистике, с `OnPaint`.
2. **Сеть.** Только через общий `Net.Http`. Запросы асинхронные, ошибки обрабатываются, UI-поток не блокируется. OpenDota — только `https://api.opendota.com/api/...`.
3. **Время.** Всё, что показывается пользователю или считается по периодам, идёт через `Msk`. В данных время хранится в UTC.
4. **Таблица истории — только для просмотра.** Не возвращать выделение, сортировку, подсказки и перетаскивание колонок.
5. **DPI и размеры.** Новые элементы проверять на разных разрешениях. Не делать окно меньше минимального размера.
6. **Версия** — при релизных изменениях обновлять подпись в боковой панели (`gl hf · vX.Y`), User-Agent в `Net` и первую строку этого файла.

### Безопасность
- Пароли и токены Steam не логировать и не хранить открыто; токен только через `Storage.Protect()`/`Unprotect()`.
- На скриншотах и в демонстрациях скрывать личные данные.

### Совместимость
- Windows 10 1809+ и Windows 11 (используется `DwmSetWindowAttribute` для тёмных рамок).
- .NET 10.0 и выше.
